# LSF 排程最佳化學習筆記:從 MILP 到 DCA 到 AI Agent

六個範例、一條學習路線:**先學會用數學算出完美班表,再學會處理數學算不動的情形,最後讓 AI 來當排程器的大腦。**

執行方式(所有範例通用):

```bash
~/.venv/bin/python <檔名>.py
```

---

## 第一段:線性世界 —— MILP 能算出「保證最優」

### 範例 1:`milp_example.py` — 入門:job 指派
- 問題:一批 job 放到 host 上,最大化完成的優先權總分。
- 學到:MILP 三要素 = **0/1 變數**(job 放哪台)、**目標函數**、**限制式**(slot 容量、license 總量)。
- 簡化之處:license 當一次性總量,搶不到就「放棄」——不符合真實情況。

### 範例 2:`milp_makespan.py` — makespan:所有 job 都要跑完
- 問題:全部跑完,讓總完工時間(makespan)最短。
- 學到:**連續變數 T 和 0/1 變數混用**(這就是 Mixed 的意思);「理論下限」的概念(總工作量 ÷ 機器數)。
- 簡化之處:完全沒有資源限制。

### 範例 3:`milp_schedule.py` — 加入時間軸,符合真實情況
- 問題:license 是**同一時刻的併發上限**,job 跑完會釋放,搶不到的要排隊等,不是消失。
- 學到:**時間離散化**(切成 5 分鐘一格)、變數變成「job j 在時間 t 於 host h 開始」、限制式改成「每個時間點的併發用量 ≤ 上限」。
- 附:單一 job 需求超過全站上限的可行性預檢(真實 LSF 會永遠 PEND)。

## 第二段:非線性世界 —— MILP 吃不下時的兩招

### 範例 4:`dca_example.py` — DCA:用直線逼近曲線
- 問題:加入「整併加分」`w·Σ load²`——曲線放進 maximize,線性求解器直接罷工。
- 學到:**DCA(Difference-of-Convex Algorithm)**:
  1. 把目標拆成「凸 − 凸」兩塊;
  2. 每輪把曲線在目前解附近**線性化**(畫一條貼著它的直線);
  3. 線性化後就是普通 MILP,解完更新再迭代;
  4. 每輪保證不變差,幾輪內收斂。
- 弱點:只保證**局部最優**(可能走進小山谷就停),實務上多試幾個起點。
- 驗證:暴力枚舉 4⁵ = 1024 種組合,確認這組資料 DCA 命中全域最優。
- DCA 和 MILP 的關係:MILP 是引擎,DCA 是外面套迴圈的駕駛。小題目可用「分段直線化」讓 MILP 直接吃曲線拿回全局保證,但開關變數會隨段數爆炸;混用法 = DCA 先衝出好答案,再給 MILP 當起跑點。

### 範例 5:`milp_session_preempt.py` — 真實 LSF:array、session license、搶佔
- 問題:三個真實條件一次到位(語意完全比照 lsf-sim 模擬器):
  - **license(rusage_shared)**:全域資源池,每個 job 派發時扣一次、整個生命週期抓著、結束才還;**被 SUSP 也不放**——搶佔救得了 slot、救不了 lic。session 父 job 算一個 job,整個 session 只吃一份;
  - **彈性 session 是「分配 slot」的模式**:n_min 起跑、有空位就一直吸、task 沒排完抓到不放、做完才逐格釋放;slot 可跨 host 拼湊。模型用寬度變數 K[t] 表達;
  - **搶佔(preempt)**:SSUSP 凍結剩餘時間、只釋放 slot;彈性 session 不可被搶佔。
- 執行結果的亮點:lic 只有 2 份時,最佳解讓 session **全速衝刺**(吸滿 4 slots 20 分鐘跑完 8 個 task)早早歸還 lic,急件 U 才拿得到——因為 B 被 SUSP 時 lic 不會放。
- 學到:
  - 階梯函數這種非線性,MILP 用 **0/1 開關變數** y 就吃得下(host 上有任務就逼 y=1,限制 Σy ≤ session 數)——不是所有非線性都要 DCA;
  - 搶佔 = 執行時段「可以斷開」;禁止搶佔 = 加一條「只准開始一次」的限制。兩個模型只差這一條;
  - 量化比較:允許搶佔 makespan 50 分,禁止搶佔 70 分,**搶佔省 20 分**,而急件兩種情況都趕上 deadline。
- 輸出有甘特圖:一橫排 = 一台機器,一格 = 10 分鐘。

### 範例 7:`milp_mode_choice.py` — session 還是 array?資源越多不一定效率越高
- 現象:工具每開一次有啟動開銷(10 分)→ 短工作各開各的超浪費(適合 session 共用一份),長工作值得平行(適合 array)。效率和資源量的關係**非線性、非單調**。
- 學到:「模式選擇」是離散選項 → **每種選法的耗時事先查表,用 0/1 開關變數選** → 查表後一切線性,MILP 照吃且保證最優。
- 重點:「短配 session、長配 array」這條規則**沒寫進模型**,只給了開銷的算法,求解器自己發現最佳配法(makespan 40 分,其他三種組合 60~70 分)。
- 附帶洞察:全 array 的機器時間 170 分,其中有用工作只有 90 分——開越多份工具浪費越多;而全 session 機器時間最省(110 分)但完工最慢(70 分)——**「快」和「省」是兩個不同目標**,要哪個由目標函數決定。

### 範例 8:`dca_milp_workflow.py` — DCA 與 MILP 的分工(工作流程三部曲)
- **第 1 部(小題目)**:非線性的 `load²` 用查表直線化(範例 7 的開關變數)變成 exact MILP,0.01 秒直接拿 Optimal 證書——驗證了範例 4 DCA 的 37.6 確實是全域最優,小題目根本不需要 DCA。
- **第 2 部(抽驗)**:10 個隨機小題目,DCA(3 起點)vs exact MILP 對答案:命中率 5/10、平均落差 1.6、最大 5.6——抽驗告訴你 DCA 在這類題目「大概多可靠」,據此決定要不要加起點數。
- **第 3 部(大題目)**:50 jobs × 10 hosts,exact MILP 給 20 秒也算不完(只回「目前最好」、無完整證書);DCA×3 起點 0.9 秒收斂,落差僅 2%——**速度差 22 倍**。
- 結論:**小題目 MILP 拿證書、大題目 DCA 換速度、中間用抽驗把關**。

## 第三段:AI 世界 —— 讓 LLM 當排程器的大腦

### 範例 6:`lsf_ai_scheduler.py` — LangGraph + Claude + 迷你模擬器
- 分工:
  - **模擬器**(遊戲場):只管世界運轉——時鐘、job 到達/跑完、slots 佔用,不做決策;
  - **LangGraph**(流程圖):observe → decide → apply 一直繞,直到全部跑完;
  - **大腦**(決策者):看 JSON 快照,決定誰上機、放哪台、要不要搶佔。
- 大腦可插拔:沒設 `ANTHROPIC_API_KEY` 用內建規則大腦;設了就自動換成 Claude(`claude-opus-5`,structured outputs 保證回傳合法 JSON)。
- 學到:
  - LangGraph 的節點是「流程步驟」,**不適合**拿來演 slot/job(沒有時鐘、沒有資源競爭、節點不能暫停);模擬世界用 SimPy 或手刻模擬器,指揮 AI 才用 LangGraph;
  - LLM 大腦的強項:**聽得懂人話**——模糊的、口語的政策直接寫進提示詞就生效;
  - LLM 大腦的弱項:不保證最優、只能對已發生的事件反應(看不到未來);
  - 底線靠程式把關(塞不下的指令標為「決策無效」略過),提示詞管方向,程式管底線。

## 三種方法一張表

| | MILP | DCA | LLM 大腦 |
|---|---|---|---|
| 適用 | 線性(或可用開關變數改寫的)問題 | 有凸−凸結構的非線性問題 | 規則模糊、口語化、常變動的政策 |
| 答案品質 | **保證全域最優**(Optimal 證書) | 保證不變差,只到局部最優 | 憑判斷,通常不錯,無保證 |
| 看得到未來 | 是(整張班表一次算完) | 是 | 否(事件驅動,臨場反應) |
| 每次結果 | 相同 | 相同(同起點) | 可能不同 |
| 改需求的成本 | 重寫數學式 | 重寫數學式 | 改一段中文提示詞 |

終極組合:**LLM 當大腦、MILP 當它的計算機**——平時 AI 自己判斷,關鍵時刻呼叫求解器精算(範例 7 候選)。

## 怎麼確認答案真的是最短?(驗證方法論)

1. **看 `Optimal` 證書**:求解器用「夾擠」——上界(找到的解)壓下來、下界(數學證明的極限)抬上去,相等即證明最優。回報 `Optimal` = 交出解 + 證明。
2. **手算下界對照**:例:B(40 分)和 U(10 分)都只塞得進 H1 → makespan ≥ 50;答案 = 50 → 鐵定最優。
3. **暴力枚舉**(小題目):範例 4 用 1024 種組合全比對。
4. **assert 檢查限制式**:驗證答案「合法」(可行);注意這和「最優」是兩件事。
5. **模型 vs 現實的落差要人把關**:時間切格(5/10 分鐘)、排程視窗上限(HORIZON)——`Optimal` 保證的是「你寫的模型」的最優,模型錯就是「錯題目的正確答案」。
6. **設了 timeLimit 的大題目**:狀態可能不是 `Optimal`,只回「目前最好 + gap」,要自己判斷 gap 夠不夠小。
